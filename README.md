# 📡 舆舟 · 全网舆情监测与危机管理平台

基于 **Vue 3 + Vite + Pinia（前端）+ Express + SQLite（后端）** 的舆情监测与危机处置演示平台。所有数据为 mock，模拟舆情采集与处置闭环。

## 技术栈

- 前端：Vue 3 + Vite + Pinia
- 后端：Node 内置 `node:sqlite` + Express，REST API
- 数据库：`server/pubmon.db`（SQLite，首次启动自动建表 + 预置示例舆情）

## 运行

```bash
npm install
npm run dev
```

前端 http://localhost:5200（Vite 已代理 `/api` 到 http://localhost:4130）。需 Node ≥ 22.13。

## 功能

- **舆情总览**：总量/正面/中性/负面/热点/负面占比统计、情感分布环形图、7 时段热度趋势、渠道来源分布、高频热词云、生效预警规则、危机速览
- **舆情列表**：按情感/渠道/关键词筛选，录入新舆情自动进行情感分析，负面舆情触发预警提示；批量导入为**可恢复任务**：幂等建档、分片执行、失败重试、进度与逐条结果回写
- **预警中心**：预警规则配置（级别/关键词/情感/热度下限/归并话题/时间窗口），规则启停、触发记录与关联舆情、单条/批量解除预警
- **危机处置**：事件建档（话题+方案+研判+邮箱）、状态流转（监测→处置→结案）、处置时间线、动作记录、事件回溯（按规则拆分统计）与结案总结

## 预警 → 危机闭环

- **话题 + 时间窗口归并**：每条规则可配置「归并话题」（留空则取命中舆情自身话题）与「时间窗口」（分钟，0=不限）。红/橙级预警触发时，命中**同话题且在窗口内**的未结案事件则并入，否则自动建档
- **同规则分别处置**：同一规则下，不同话题、或同一话题但已超出时间窗口的触发，分别创建独立危机事件
- **多规则承接**：一个危机事件可同时承接多条规则（多对多）；新规则并入既有同话题事件时标记来源规则，并在时间线记录「规则归并」
- **状态同步**：预警解除 → 危机时间线同步记录（标注来源规则）；危机结案 → 级联解除关联的全部未解除预警（可能横跨多条规则）
- **回溯结案**：危机事件支持回溯（按规则拆分的触发统计、关联舆情、完整时间线），结案时写入回溯总结完成闭环

## 批量导入（可恢复任务）

大批量导入以「任务」形式执行，与单条录入共用同一管线（情感分析 → 落库 → 预警触发 → 红/橙级危机建档/归并），保证大批量数据与预警危机闭环可靠衔接：

- **幂等标识**：`POST /api/import/jobs` 携带 `idempotencyKey`（前端按导入内容哈希生成），同键重复提交/中断重提返回同一任务，不产生重复批次；已完成任务重复执行不会重复落库
- **分片执行**：`POST /api/import/jobs/:id/run`（`{ limit }`，≤500/片）逐片推进；每条独立事务（舆情落库 + 预警/危机闭环 + 进度回写同生共死），单条失败隔离不影响整批
- **进度记录**：`import_jobs`（总量/已处理/成功/失败）与 `import_items`（逐条状态、尝试次数）实时落库，服务重启后任务可从断点恢复；`GET /api/import/jobs/:id` 查询进度
- **失败重试**：失败条目在后续 run 中自动重试（单条最多 3 次）；`POST /api/import/jobs/:id/retry` 重置失败条目恢复重试额度，再 run 即可续跑
- **结果回写**：每条结果（舆情 id、情感、触发的预警/危机明细）回写 `import_items`，任务级汇总（预警次数、危机建档/并入数、最新统计）回写 `import_jobs.summary`；任务状态 `pending/running/done/partial/failed`
- 单任务最多 2000 条；前端按 50 条/片循环推进，实时显示进度条，中断后可「继续导入」断点续传，部分失败可一键「重试失败项」

兼容端点：`POST /api/posts/batch`（整批事务、任一失败整体回滚，单次最多 200 条）与 `POST /api/posts` 单条录入保持原有行为不变。
